# 100L 鱼缸温度控制器原理图设计

## 1. 设计目标

本原理图用于落实 100L 鱼缸温度控制器第一版硬件实现，默认采用以下架构：

- 主控：ESP32-S3-DevKitC-1
- 温度检测：2 路 DS18B20 防水探头
- 显示：I2C OLED，SSD1306，128 x 64
- 加热输出：继电器控制成品加热棒
- 制冷输出：继电器控制风扇或冷水机
- 报警：有源蜂鸣器
- 人机输入：3 个按键，可选

第一版目标是先做稳定可运行原型，因此不把 PTC 和半导体制冷片直接画成默认主回路，只预留兼容思路。

可直接用于落图的分页与连线清单见 [原理图实施稿-交流版V1.md](%E5%8E%9F%E7%90%86%E5%9B%BE%E5%AE%9E%E6%96%BD%E7%A8%BF-%E4%BA%A4%E6%B5%81%E7%89%88V1.md)。

## 2. 原理图分块

建议整张原理图分成 6 个部分：

- 电源输入与分配
- ESP32 主控最小系统
- 双 DS18B20 温度采集
- OLED 显示与按键输入
- 加热与制冷控制输出
- 蜂鸣器与报警接口

## 3. 电源部分

### 3.1 电源输入

建议设置两个输入端子：

- J1：5V 控制电源输入
- J2：执行器电源或交流负载接口

第一版推荐：

- 控制侧统一使用 5V 电源适配器
- ESP32 通过 VIN 或 5V 引脚供电
- OLED、继电器模块、有源蜂鸣器从低压侧取电

### 3.2 电源分配

建议电源网络命名如下：

- +5V_CTRL：控制系统 5V
- +3V3：ESP32 板上稳压输出
- GND：控制地

执行器部分：

- AC_HEAT_L / AC_HEAT_N：加热器交流输入
- AC_COOL_L / AC_COOL_N：制冷器交流输入

### 3.3 去耦建议

建议在以下位置加去耦：

- OLED 供电端并联 0.1uF 陶瓷电容
- 蜂鸣器供电端并联 0.1uF 电容
- 若自制驱动板上放继电器控制电路，5V 侧建议增加 10uF 电解电容

### 3.4 硬件安全兜底建议

当前软件已经具备双探头故障停机、绝对高低温切断和输出互锁，但鱼缸长期运行仍建议增加独立硬件保护链。

建议至少加入以下兜底措施：

- 加热支路串联独立温控器或热保护开关，设定值高于正常控温目标、低于危险温度
- 加热支路串联一次性热熔断器，作为最终失效保护
- 控制电源输入增加保险丝或自恢复保险丝
- 继电器线圈和外设 5V 电源入口增加 TVS 或浪涌吸收器件
- 若交流负载较大，继电器触点侧增加 RC 吸收或压敏电阻

推荐原则：

- 软件负责正常控制与告警
- 独立温控器负责硬件级过温断开
- 热熔断器负责极端失效场景的最终保护

## 4. ESP32 主控部分

### 4.1 主控器件

主控 U1 采用 ESP32-S3-DevKitC-1 模块化板卡，第一版不自行绘制裸芯片最小系统。

当前固件配置对应：

- 板卡：ESP32-S3-DevKitC-1
- Flash：16MB
- 外挂存储：启用 QSPI PSRAM

这样做的理由：

- 开发快
- 稳定性更高
- 后续程序调试方便
- 16MB Flash 和 PSRAM 有利于后续网页、日志和显示缓冲扩展

### 4.2 GPIO 分配

| 网络名 | ESP32 引脚 | 功能 |
| --- | --- | --- |
| TEMP_A | GPIO4 | DS18B20-A 数据 |
| TEMP_B | GPIO16 | DS18B20-B 数据 |
| I2C_SDA | GPIO8 | OLED SDA |
| I2C_SCL | GPIO9 | OLED SCL |
| HEAT_CTRL | GPIO19 | 加热控制 |
| COOL_CTRL | GPIO18 | 制冷控制 |
| BUZZ_CTRL | GPIO15 | 蜂鸣器控制 |
| KEY_SET | GPIO12 | 设置键，可选 |
| KEY_UP | GPIO13 | 加号键，可选 |
| KEY_DOWN | GPIO14 | 减号键，可选 |

## 5. 双 DS18B20 温度采集部分

### 5.1 探头 A

器件：

- U2：DS18B20-A
- R1：4.7k 上拉电阻

连接关系：

- U2 VDD 接 +3V3
- U2 GND 接 GND
- U2 DQ 接 TEMP_A
- R1 一端接 TEMP_A，另一端接 +3V3

### 5.2 探头 B

器件：

- U3：DS18B20-B
- R2：4.7k 上拉电阻

连接关系：

- U3 VDD 接 +3V3
- U3 GND 接 GND
- U3 DQ 接 TEMP_B
- R2 一端接 TEMP_B，另一端接 +3V3

### 5.3 设计说明

两只探头不共用同一 1-Wire 总线，原因如下：

- 软件逻辑更简单
- 故障定位更直接
- 现场接线更不容易混乱

## 6. OLED 显示部分

### 6.1 显示器件

器件：

- U4：1.3 寸 OLED，SSD1306，I2C 接口

连接关系：

- U4 VCC 接 +3V3 或 +5V_CTRL，按模块规格决定
- U4 GND 接 GND
- U4 SDA 接 I2C_SDA
- U4 SCL 接 I2C_SCL

### 6.2 注意事项

- 默认 I2C 地址按 0x3C 设计
- 若采购模块地址为 0x3D，仅需修改程序初始化参数
- 首版建议把 OLED 供电直接定为 3.3V，减少电平兼容不确定性

## 7. 按键输入部分

按键部分为可选，但建议原理图预留。

器件：

- SW1：SET
- SW2：UP
- SW3：DOWN

推荐接法：

- 每个按键一端接 GND
- 另一端分别接 KEY_SET、KEY_UP、KEY_DOWN
- 软件内部开启 ESP32 上拉输入

这样可以减少外部电阻数量，适合第一版原型。

## 8. 加热控制部分

### 8.1 第一版默认实现

第一版加热输出默认采用继电器控制成品加热棒。

器件：

- K1：加热继电器模块输入
- J3：加热器交流输出端子

控制关系：

- HEAT_CTRL 接继电器模块 IN1
- 继电器模块 VCC 接 +5V_CTRL
- 继电器模块 GND 接 GND

负载关系：

- AC_HEAT_L 经 K1 常开触点后输出到加热器火线
- AC_HEAT_N 直接接加热器零线

### 8.2 设计注意事项

- 交流负载建议走独立端子台
- 加热继电器触点容量要满足加热棒电流
- 若使用固态继电器，也保持 HEAT_CTRL 网络名不变，后续程序无需调整
- 如果加热棒为交流型，建议优先采用“主控继电器 + 独立过温保护器 + 热熔断器”三级链路

## 9. 制冷控制部分

### 9.1 第一版默认实现

第一版制冷输出默认同样采用继电器控制。

器件：

- K2：制冷继电器模块输入
- J4：制冷器输出端子

控制关系：

- COOL_CTRL 接继电器模块 IN2
- 继电器模块 VCC 接 +5V_CTRL
- 继电器模块 GND 接 GND

负载关系：

- AC_COOL_L 经 K2 常开触点后输出到制冷器火线
- AC_COOL_N 直接接制冷器零线

### 9.2 风扇兼容方式

如果第一版制冷器用低压风扇，也可以临时用继电器控制其电源通断。

但如果后续确定长期使用直流风扇，建议第二版把该回路改成 MOS 驱动。

如果后续要把硬件方案分版，建议直接拆成两套：

- 交流负载版：加热棒 / 冷水机，采用继电器或固态继电器
- 低压直流版：PTC / 风扇 / 水泵，采用 MOS 驱动

详细建议可见 [执行器驱动分版建议.md](%E6%89%A7%E8%A1%8C%E5%99%A8%E9%A9%B1%E5%8A%A8%E5%88%86%E7%89%88%E5%BB%BA%E8%AE%AE.md)。

## 10. 蜂鸣器部分

器件：

- BZ1：有源蜂鸣器

推荐连接：

- 若蜂鸣器工作电流较小，可由 BUZZ_CTRL 经三极管驱动
- 若直接使用现成蜂鸣器模块，可让 BUZZ_CTRL 接模块输入端

第一版建议：

- 直接采购带驱动的有源蜂鸣器模块，简化原理图

## 12. 网络连接总览

核心网络如下：

- +5V_CTRL：给继电器模块和外设供电
- +3V3：给 DS18B20 和 OLED 供电
- GND：控制系统地
- TEMP_A：探头 A 数据
- TEMP_B：探头 B 数据
- I2C_SDA：OLED 数据
- I2C_SCL：OLED 时钟
- HEAT_CTRL：加热输出控制
- COOL_CTRL：制冷输出控制
- BUZZ_CTRL：蜂鸣器控制

## 13. 端子与接口定义（建议冻结）

为避免后续接线和装配歧义，建议首版固定以下端子定义：

- J1（控制电源输入）：1=+5V_CTRL，2=GND
- J2（探头接口）：1=+3V3，2=TEMP_A，3=TEMP_B，4=GND
- J3（加热负载接口）：1=AC_HEAT_L_OUT，2=AC_HEAT_N_OUT
- J4（制冷负载接口）：1=AC_COOL_L_OUT，2=AC_COOL_N_OUT
- J5（按键接口，可选）：1=KEY_SET，2=KEY_UP，3=KEY_DOWN，4=GND

若后续拆分低压直流版，建议另起端子命名，不复用 AC 网络名。

## 14. 保护器件与建议参数

以下参数用于首版器件选型参考，最终以负载额定电流与本地安规要求复核：

- F1（控制电源保险丝）：1A 慢断（5V 输入侧）
- F2（加热支路保险丝）：按加热棒电流 1.5 到 2 倍选型
- F3（制冷支路保险丝）：按制冷器额定电流选型
- MOV1（交流浪涌吸收）：471 规格压敏，跨 AC L-N
- RC1/RC2（继电器触点吸收，可选）：100R + 100nF X2 串联
- TS1（独立温控保护开关）：建议 35 到 40 摄氏度区间按设备工况选择
- TF1（一次性热熔断器）：与 TS1 串联，作为最终失效保护

说明：

- TS1 与 TF1 建议放在加热链路，物理上靠近热源风险区域。
- 继电器模块若自带吸收和隔离，仍建议在系统级图纸中保留保护位号与说明。

## 15. PCB 与安规布线规则（首版）

若进入自制 PCB，建议至少满足：

- 高压区与低压控制区明确分区，禁止跨区走线混布
- 交流 L/N 与低压网络保持足够爬电与电气间隙
- 继电器触点区、交流端子区预留安全禁布区
- 探头信号线、I2C 线远离继电器和交流走线
- 控制地与大电流地采用单点汇聚，避免传感器地被大电流回路污染

## 16. 首版硬件联调前检查清单

上电前建议逐项确认：

1. TEMP_A/TEMP_B 均已上拉 4.7k 至 +3V3
2. OLED 供电电压与模块规格一致（优先 3.3V）
3. HEAT_CTRL 与 COOL_CTRL 未接反
4. 继电器常开触点与负载火线串联关系正确
5. 蜂鸣器极性与驱动方式匹配
6. 按键下拉到地，GPIO 内部上拉已启用
7. 控制电源与执行器电源地参考关系符合设计
8. 交流负载联调阶段已配置漏保和隔离防护

## 17. 第一版原理图结论

第一版原理图推荐固定为：

- ESP32-S3-DevKitC-1
- 双 DS18B20 独立接入
- I2C OLED
- 两路继电器输出
- 三按键预留
- 蜂鸣器预留

这样做的好处是：

- 电路简单
- 调试成本低
- 后续程序编写边界清晰
- 第二版若要切换 PTC 或 MOS 驱动，也只改执行器部分，不影响主控和测温显示部分

如果进入第二版硬件，建议优先完成两件事：

- 给加热链路加入独立硬件过温保护
- 按交流负载版 / 低压直流版拆分执行器驱动原理图
