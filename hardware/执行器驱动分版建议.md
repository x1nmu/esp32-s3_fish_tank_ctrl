# 100L 鱼缸温度控制器执行器驱动分版建议

## 1. 目的

本文件用于把当前统一描述的执行器驱动方案拆成两条更清晰的硬件路线：

- 交流负载版
- 低压直流版

这样做的原因是鱼缸温控器的加热和制冷设备类型差异很大，继续混用一套接线说明，会在原理图、BOM 和联调阶段制造歧义。

## 2. 推荐分版方式

### 2.1 交流负载版

适用设备：

- 成品加热棒
- 冷水机
- 交流循环泵

推荐驱动：

- 机械继电器
- 固态继电器

推荐特点：

- 结构简单
- 适合第一版快速落地
- 便于直接控制成熟成品设备

必须补充的安全设计：

- 继电器触点容量按额定电流留足余量
- 火线侧串联触点，零线直通
- 加热支路增加独立过温保护器和热熔断器
- 交流侧增加保险丝、压敏电阻或 RC 吸收网络
- 高压区与低压控制区明确分区，满足绝缘间距要求

### 2.2 低压直流版

适用设备：

- 直流风扇
- 低压 PTC 模块
- 低压水泵
- TEC 实验模块

推荐驱动：

- 逻辑级 N-MOS 管
- 栅极串联电阻
- 下拉电阻
- 感性负载并联续流二极管

推荐特点：

- 寿命更长
- 无继电器吸合噪声
- 适合高频或较频繁启停场景

必须补充的安全设计：

- 执行器电源与控制电源分离
- 大电流回路单独走线，不与传感器回路混布
- TEC 或 PTC 回路增加独立温控或电流保护
- 风扇和水泵等感性负载增加反灌保护

## 3. 当前项目建议

### 3.1 第一版推荐落地

第一版继续推荐：

- 加热：交流加热棒 + 继电器
- 制冷：风扇或冷水机

其中：

- 如果制冷设备最终选冷水机，继续采用继电器方案
- 如果制冷设备最终选直流风扇，建议制冷支路优先切换到 MOS 驱动

### 3.2 第二版推荐拆分

建议至少拆出两张执行器原理图：

- 执行器-交流版：Heat Relay + Cool Relay
- 执行器-直流版：Heat MOS + Cool MOS

这样做的好处：

- 原理图更清晰
- BOM 更准确
- 联调时不会混淆接线方式
- 后续更容易扩展到不同鱼缸和不同执行器组合

## 4. 接线与网络命名建议

无论采用哪一版，控制信号网络建议保持不变：

- HEAT_CTRL
- COOL_CTRL

这样软件层无需感知底层是继电器还是 MOS，只在硬件层替换驱动级。

交流版推荐负载网络：

- AC_HEAT_L
- AC_HEAT_N
- AC_COOL_L
- AC_COOL_N

低压直流版推荐负载网络：

- DC_HEAT_V+
- DC_HEAT_GND_SW
- DC_COOL_V+
- DC_COOL_GND_SW

## 5. 硬件安全优先级建议

优先级从高到低建议如下：

1. 加热链路的独立过温保护
2. 交流高低压隔离和保险丝配置
3. 大电流直流回路的线宽和接地设计
4. 继电器吸收网络或 MOS 反灌保护
5. 执行器寿命与维护便利性

## 6. 结论

当前项目不建议继续用一套原理图同时兼顾交流型执行器和低压直流执行器。

更合理的做法是：

- 第一版按交流负载版稳定落地
- 第二版再按低压直流版扩展

这样能明显降低硬件歧义和联调风险。
