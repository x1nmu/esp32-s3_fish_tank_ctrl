# 100L 鱼缸温度控制器模块接线与控制细化

## 1. 文档目的

本文件用于把总体方案细化为后续可直接落到原理图、接线图和程序设计中的工程内容。

重点覆盖：

- 模块连接关系
- 推荐接线方式
- 控制状态机
- 控制流程
- 故障检测和保护策略
- PTC 加热与半导体制冷片的接入建议

当前版本说明：

- 本文档已按 V1 软件实现状态同步修订
- 固件主线目录为 `firmware/esp32_idf`

## 2. 模块划分

系统建议拆成 6 个功能模块：

- 控制核心模块
- 温度采集模块
- 显示与人机交互模块
- 加热执行模块
- 制冷执行模块
- 电源与保护模块

## 3. 模块连接关系

### 3.1 控制核心模块

主控采用 ESP32 开发板，负责：

- 读取两路温度探头
- 运行控温算法
- 控制加热与制冷输出
- 刷新 OLED 显示
- 提供 WiFi 状态查看页面
- 记录和上报故障状态

### 3.2 温度采集模块

采用两只 DS18B20 防水探头。

连接原则：

- 每只探头单独占用一个 GPIO
- 每一路数据线单独使用一个 4.7k 上拉电阻到 3.3V
- 两个探头不建议直接并在同一总线上作为首版方案

这样做的原因是：

- 便于区分每个探头的硬件故障
- 接线和软件逻辑都更直观
- 后续排障更方便

### 3.3 显示与交互模块

显示模块采用 SSD1306 OLED，I2C 接口。

本项目显示接口正式固定为 I2C，不再预留 SPI 切换方案。

推荐显示模块参数：

- 尺寸：1.3 寸
- 分辨率：128 x 64
- 驱动芯片：SSD1306 优先
- 接口：I2C
- 默认地址：0x3C

当前本地交互已固定为 3 键极简模式：

- SET：短按切换蜂鸣器开关
- UP：增加目标温度（短按 0.1，长按快调）
- DOWN：降低目标温度（短按 0.1，长按快调）

维护组合键：

- 长按 SET + UP：清除锁定故障
- 长按 SET + DOWN：清零运行统计

### 3.4 加热执行模块

第一版建议用成品加热棒，主控只负责开关控制。

可选两种接法：

- 交流加热棒：继电器或固态继电器控制交流侧通断
- 低压 PTC 模块：MOS 管控制低压直流供电

### 3.5 制冷执行模块

按目标功能分为三类：

- 轻度降温：直流风扇
- 稳定降温：冷水机或压缩机制冷机
- 实验验证：半导体制冷片外置换热模块

### 3.6 电源与保护模块

建议至少分为两路供电：

- 控制电源：5V，给 ESP32、OLED、继电器控制侧供电
- 执行器电源：按执行器类型配置 12V、24V 或交流市电

如果采用 TEC 或大功率 PTC，执行器电源必须独立，不要与控制系统共用小电源。

## 4. 推荐接线表

### 4.1 ESP32 引脚定义

| 功能 | 器件 | ESP32 引脚 | 备注 |
| --- | --- | --- | --- |
| 探头 A 数据 | DS18B20-A | GPIO4 | 单独一路 1-Wire |
| 探头 B 数据 | DS18B20-B | GPIO16 | 单独一路 1-Wire |
| OLED SDA | SSD1306 | GPIO8 | I2C 数据 |
| OLED SCL | SSD1306 | GPIO9 | I2C 时钟 |
| 加热控制 | Relay/MOS | GPIO19 | 加热输出 |
| 制冷控制 | Relay/MOS | GPIO18 | 制冷输出 |
| 蜂鸣器 | Buzzer | GPIO15 | 可选 |
| 按键 SET | Key | GPIO12 | 可选 |
| 按键 UP | Key | GPIO13 | 可选 |
| 按键 DOWN | Key | GPIO14 | 可选 |

### 4.2 双探头接线规则

探头 A：

- 红线接 3.3V
- 黑线接 GND
- 黄线或白线接 GPIO4
- GPIO4 通过 4.7k 电阻上拉到 3.3V

探头 B：

- 红线接 3.3V
- 黑线接 GND
- 黄线或白线接 GPIO16
- GPIO16 通过 4.7k 电阻上拉到 3.3V

布置建议：

- 探头 A 靠近出水口或加热器附近，观察局部快速变化
- 探头 B 靠近鱼缸中部或远离热源位置，反映主体水温

### 4.3 OLED 接线

- VCC 接 3.3V 或 5V，按模块规格决定
- GND 接 GND
- SDA 接 GPIO8
- SCL 接 GPIO9

当前默认硬件平台已调整为 ESP32-S3-DevKitC-1，固件配置为 16MB Flash 并启用 QSPI PSRAM。

实施建议：

- 优先购买标注为 I2C SSD1306 的 4 针模块
- 如果模块板载电平兼容和稳压完善，可直接接 5V 供电
- 如果模块只支持 3.3V，必须接 3.3V 供电
- 首版原型建议把 VCC 接法在丝印或接线图中明确写死，避免现场接错
- I2C 地址默认按 0x3C 处理，代码里保留 0x3D 兼容

如果 OLED 与主控距离较近，一般不需要额外上拉；如果连线较长或模块表现不稳定，再评估是否补 I2C 上拉电阻。

### 4.4 继电器或 MOS 驱动接线

#### 交流加热棒或冷水机

推荐使用继电器模块：

- 加热继电器输入接 GPIO19
- 制冷继电器输入接 GPIO18
- 继电器模块电源接 5V 与 GND
- 交流负载接在继电器触点侧

注意：

- 交流火线侧串联继电器触点
- 低压控制部分与高压部分物理隔离
- 继电器触点电流容量要大于负载额定电流

#### 低压 PTC 或风扇

推荐使用 MOS 驱动：

- GPIO 输出接 MOS 驱动输入
- 负载电源正极直接接执行器电源正极
- 负载负极通过 MOS 管开关到地
- 电源地与控制地单点共地

## 5. 两种加热方案的落地方式

### 5.1 第一版推荐：成品加热棒

适合先快速做出可靠原型。

特点：

- 硬件简单
- 鱼缸适配性好
- 维护成本低

建议：

- 加热棒自身设定略高于系统目标温度，真正启停由主控继电器决定
- 如果加热棒本身无法设置，可选固定温控型，但外部仍要有上位保护策略

### 5.2 进阶方案：外置 PTC 加热模块

推荐结构：

- PTC 发热体
- 金属换热腔体
- 小型水泵或循环水路
- 温度保护开关或熔断器

不建议的方式：

- 裸 PTC 发热片直接接触鱼缸水体
- 没有防水和绝缘设计就直接上电

PTC 方案适合你想做“完整自主硬件结构”时再推进。

## 6. 两种制冷方案的落地方式

### 6.1 第一版推荐：风扇或冷水机

风扇方案适合：

- 环境只是略高于目标温度
- 允许蒸发量增加
- 只需要辅助降温

冷水机方案适合：

- 夏季环境温度持续高
- 目标温度低于室温较多
- 需要稳定长期运行

### 6.2 可研究方案：半导体制冷片

如果你要研究 TEC，建议结构必须包括：

- 半导体制冷片
- 冷端换热块
- 热端大面积散热器
- 强制风冷风扇
- 独立大电流电源
- 冷凝水处理结构

关键问题：

- 热端散热不充分时，冷端性能会快速恶化
- 冷端可能产生冷凝水，必须防滴水和绝缘
- 对 100L 鱼缸而言，低成本 TEC 方案很难形成长期稳定制冷能力

因此 TEC 可以写进预研项，但不建议作为首版实施项。

## 7. 控制状态机设计

建议系统定义以下状态：

- INIT：初始化
- IDLE：待机监测
- HEATING：加热中
- COOLING：制冷中
- DEGRADED：单探头降级运行
- ALARM：告警但可继续运行
- FAULT_STOP：故障停机

### 7.1 状态说明

#### INIT

执行内容：

- 初始化 GPIO
- 初始化 OLED
- 初始化两个温度探头
- 初始化 WiFi
- 读取参数

满足条件后进入 IDLE。

#### IDLE

执行内容：

- 周期采样温度
- 计算控制温度
- 判断是否需要加热或制冷

转移条件：

- 温度低于下阈值，转 HEATING
- 温度高于上阈值，转 COOLING
- 单探头异常，转 DEGRADED
- 双探头异常，转 FAULT_STOP

#### HEATING

执行内容：

- 打开加热输出
- 保证制冷输出关闭
- 连续监测温度和探头状态

退出条件：

- 温度回到目标区间，转 IDLE
- 探头异常，按情况转 DEGRADED 或 FAULT_STOP

#### COOLING

执行内容：

- 打开制冷输出
- 保证加热输出关闭
- 对压缩机类设备执行最小停机保护

退出条件：

- 温度回到目标区间，转 IDLE
- 探头异常，按情况转 DEGRADED 或 FAULT_STOP

#### DEGRADED

执行内容：

- 仅使用剩余正常探头控温
- 上报探头故障
- 允许短期继续运行

退出条件：

- 故障探头恢复，转 IDLE
- 剩余探头也失效，转 FAULT_STOP

#### ALARM

适用场景：

- 双探头温差过大
- WiFi 断开
- 制冷保护计时中

该状态不一定停机，但必须告警显示。

#### FAULT_STOP

执行内容：

- 关闭加热输出
- 关闭制冷输出
- 蜂鸣器报警
- 显示故障原因

恢复方式：

- 自动恢复或人工确认后重新回到 INIT 或 IDLE

## 8. 控制流程细化

### 8.1 主循环流程

V1 当前实现为 FreeRTOS 多任务架构，不是单一 while 主循环。

任务拆分如下：

1. 控制任务：按键处理、蜂鸣器处理、参数保存、命令队列消费
2. 采样任务：探头采样、状态机更新
3. 网络任务：WiFi 维护、STA/AP 回退
4. 显示任务：OLED 页面刷新
5. 日志任务：周期状态日志输出

并发模型：

- 共享运行态通过互斥锁保护
- 网页写操作通过命令队列串行下发，由控制任务统一执行
- 网页读操作通过运行态快照读取，降低并发冲突风险

### 8.2 探头有效性判断

建议按以下顺序判断：

1. 是否读取超时
2. 是否 CRC 失败
3. 是否温度超出合理范围，例如低于 0 摄氏度或高于 50 摄氏度
4. 是否长时间固定不变且不符合实际环境变化

### 8.3 控温阈值

假设：

- $T_{set} = 26$
- $\Delta T = 0.5$

则：

- 低于 25.5 摄氏度，进入加热判断
- 高于 26.5 摄氏度，进入制冷判断
- 位于 25.5 到 26.5 摄氏度之间，保持待机

### 8.4 执行器互锁规则

任一时刻：

- 加热输出与制冷输出不能同时为开启状态
- 进入加热前先确认制冷已经关闭
- 进入制冷前先确认加热已经关闭

当前 V1 已落地互锁控制，并实现最小导通/停机保护参数控制。

## 9. 故障处理表

| 故障编号 | 故障类型 | 触发条件 | 系统动作 | 是否停机 | 远程上报 |
| --- | --- | --- | --- | --- | --- |
| F01 | 探头 A 失效 | 连续读取失败或数值异常 | 切换单探头模式并告警 | 否 | 是 |
| F02 | 探头 B 失效 | 连续读取失败或数值异常 | 切换单探头模式并告警 | 否 | 是 |
| F03 | 双探头失效 | 两路均不可用 | 关闭所有输出，进入故障停机 | 是 | 是 |
| F04 | 双探头温差过大 | 两探头温差大于阈值 | 告警，继续观察 | 否 | 是 |
| F05 | 加热输出异常 | 输出开启但温度长时间不升 | 告警，建议人工检查 | 否 | 是 |
| F06 | 制冷输出异常 | 输出开启但温度长时间不降 | 告警，建议人工检查 | 否 | 是 |
| F07 | 压缩机保护中 | 未达到最小停机时间 | 禁止立即启动制冷 | 否 | 是 |
| F08 | 电源异常 | 控制电压不稳定或模块掉线 | 关闭输出并重启或停机 | 视情况 | 是 |
| F09 | WiFi 断开 | 网络连接丢失 | 本地继续控温，显示离线 | 否 | 否 |

说明：

- 以上故障编号为设计层建议编号，用于工程文档沟通。
- 代码中当前使用故障枚举与短码（如 `SNS_A`、`SNS_B`、`LOW_CUT`、`HIGH_CUT`），二者语义一致。

## 10. 报警策略建议

报警分成三级：

- 一级提示：WiFi 断开、探头差值偏大
- 二级告警：单探头失效、执行器疑似失效
- 三级故障：双探头失效、电源异常、系统停机

蜂鸣器策略建议：

- 一级提示：短鸣 1 次
- 二级告警：间隔鸣叫
- 三级故障：持续鸣叫，直到人工确认

## 11. 页面显示建议

### 11.1 OLED 页面

本项目 OLED 页面当前为单页核心信息布局（I2C 128 x 64）：

- 状态（Mode）
- 当前控制温度（Ctrl）
- 目标温度（Set）
- 加热/制冷状态（H/C）
- 网络简要信息

### 11.2 Web 页面

当前网页建议至少显示：

- 当前控制温度与目标温度
- 当前模式与故障码
- 加热/制冷状态
- 蜂鸣器状态
- 网络标签与 IP

当前网页交互建议：

- 控制参数区默认简洁，仅突出目标温度；高级参数折叠展示
- WiFi 密码输入框不回显已保存密码，留空表示不修改密码
- 保存 WiFi 后提示“正在重连”，并自动轮询刷新
- 页面顶部固定显示访问入口（同网 URL + AP 配网入口）

## 12. 建议的工程推进顺序

建议按下面顺序推进，风险最低：

1. 先做双探头测温和 OLED 显示
2. 再接加热输出，验证控温闭环
3. 再接制冷输出，加入互锁和保护
4. 最后加 Web 页面和故障上报
5. 最后再评估 PTC 和 TEC 的进阶版本

## 13. 当前推荐落地版本

如果目标是先做出一版真正可用的 100L 鱼缸温控器，推荐版本如下：

- ESP32 主控
- 2 路 DS18B20
- OLED 显示
- 加热棒继电器控制
- 风扇或冷水机制冷
- Web 页面远程查看
- 蜂鸣器故障告警

这一版实现成本、复杂度和可靠性相对平衡，适合作为正式第一版。

## 14. V1 已知约束

- 当前 I2C 显示驱动使用 legacy I2C API。
- 已启用 `CONFIG_I2C_SUPPRESS_DEPRECATE_WARN` 抑制 EOL 编译提示。
- 后续在本机 ESP-IDF 环境具备新 I2C 主机头文件后，再迁移到新 I2C 主机 API。
