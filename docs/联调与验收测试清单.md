# 100L 鱼缸温度控制器联调与验收测试清单

## 1. 目的

本清单用于把当前方案落成一套可执行的联调和验收流程，避免只验证“能运行”，而忽略长期运行中的安全和可靠性风险。

当前版本范围：

- 本清单对应软件 V1（ESP-IDF 主线）
- 固件目录：`firmware/esp32_idf`

## 2. 联调前准备

联调前应确认：

- 固件已按当前目标板编译通过
- 主控板、电源、探头、显示、按键和执行器接线已复核
- 加热和制冷支路在首次联调时可先断开真实大功率负载，改用指示灯或小功率替代负载
- 交流负载联调时已配置漏保、保险丝和隔离电源

建议补充：

- 已确认 `sdkconfig` 与 `sdkconfig.defaults` 为本次联调版本
- 已记录串口号、编译时间、固件版本号

## 3. 基础上电检查

### 3.1 上电静态检查

检查项：

- 主控正常启动
- OLED 正常点亮
- 串口输出启动日志
- 加热、制冷默认保持关闭
- 蜂鸣器不上电误鸣

验收标准：

- 启动 10 秒内无异常复位
- 上电保护期间输出保持关闭

### 3.2 电源稳定性检查

检查项：

- WiFi 初始化时是否掉电复位
- 继电器吸合时 OLED 是否闪屏
- 蜂鸣器鸣叫时系统是否重启

验收标准：

- 任意单一外设动作时，主控不重启、不丢显示、不异常断网

## 4. 传感器联调

### 4.1 双探头正常采样

检查项：

- 两只 DS18B20 都能稳定读数
- 两路温度变化趋势合理
- 控制温度为双探头平均值

验收标准：

- 室温稳定时两探头差值不超过设定告警阈值

### 4.2 单探头断线测试

操作：

- 断开探头 A，再断开探头 B，分别测试

验收标准：

- 系统进入降级模式
- 网页和 OLED 能显示探头故障
- 仍可由剩余探头继续控温

### 4.3 双探头失效测试

操作：

- 同时断开两只探头

验收标准：

- 系统进入故障停机
- 加热和制冷输出全部关闭
- 故障原因可在网页和 OLED 上识别

### 4.4 温差超限测试

操作：

- 人为让两探头处于明显不同温区

验收标准：

- 系统进入告警状态
- 不出现加热和制冷同时开启
- 网页可看到探头差值超限提示

## 5. 加热链路测试

### 5.1 正常加热测试

操作：

- 让控制温度低于目标温度减回差

验收标准：

- 加热输出开启
- 制冷输出保持关闭
- 温度回到范围后加热关闭

### 5.2 加热互锁测试

操作：

- 在加热进行中人为提高温度，检查制冷切换

验收标准：

- 系统不会出现加热与制冷同时开启
- 切换过程符合最短动作时间限制

### 5.3 加热异常测试

操作：

- 模拟加热输出开启但水温不升

验收标准：

- 系统产生异常提示
- 人员可根据日志判断为执行器或加热设备异常

## 6. 制冷链路测试

### 6.1 正常制冷测试

操作：

- 让控制温度高于目标温度加回差

验收标准：

- 制冷输出开启
- 加热输出保持关闭
- 温度回到范围后制冷关闭

### 6.2 最小停机保护测试

操作：

- 连续触发制冷启停条件

验收标准：

- 压缩机类设备在保护时间内不会被立即重复启动
- 网页或日志能看到保护状态

## 7. 保护与安全测试

### 7.1 绝对高温切断测试

操作：

- 模拟控制温度超过安全上限

验收标准：

- 系统进入锁定停机
- 输出全部关闭
- 必须人工复位后才能恢复

### 7.2 绝对低温切断测试

操作：

- 模拟控制温度低于安全下限

验收标准：

- 系统进入锁定停机
- 输出全部关闭
- 故障记录正确

### 7.3 掉电恢复测试

操作：

- 运行中断电再上电

验收标准：

- 参数保持正确
- 统计项按设计保留或清零
- 系统能重新进入正常监控

## 8. 网络与界面测试

### 8.1 WiFi 正常连接测试

验收标准：

- 设备成功连入路由器
- 网页能查看状态
- /status 接口返回完整 JSON
- 前端周期刷新下页面数据持续更新，无明显卡死或错乱

### 8.2 AP 回退测试

操作：

- 输入错误 WiFi 参数或关闭路由器

验收标准：

- 设备切换到 AP 配网模式
- 可通过热点重新配置网络
- AP 空闲达到超时后，设备会自动重试 STA 连接

补充验收（当前版本）：

- 当无有效 STA 凭据时，设备上电后直接进入 AP 配网（不等待 STA 超时）

### 8.4 网页并发写入测试（V1 新增）

操作：

- 在网页连续快速提交设置（目标温度、回差、蜂鸣器、WiFi 参数）
- 同时观察串口日志与页面刷新

验收标准：

- 设置提交能返回明确成功/失败信息
- 参数最终值与最新一次提交一致
- 系统不崩溃、不重启
- 无持续性“runtime busy”错误风暴

### 8.5 设置拆分保存行为测试（V1 新增）

操作：

- 在 /settings/control 修改目标温度、回差、蜂鸣器
- 在 /settings/wifi 修改 WiFi SSID 或密码

验收标准：

- 控制参数保存后，页面状态刷新且 WiFi 不主动断连重连
- WiFi 参数保存后，系统触发 WiFi 重连流程
- 两类保存互不干扰，最终参数与最新提交一致

补充验收（当前版本）：

- WiFi 密码输入框默认不回显历史密码
- WiFi 密码留空提交时，系统保持旧密码不变
- WiFi 保存后页面出现重连提示并自动轮询刷新，无需手动复位

### 8.6 采样节拍与日志观测测试（V1 新增）

操作：

- 设备稳定运行 5 分钟，记录串口周期状态日志
- 在探头正常接入与单探头短时抖动两种场景下分别观察日志

验收标准：

- 串口日志持续输出 SAMPLE / MAX / CONV_AGE 字段
- SAMPLE 在稳定场景下无持续性异常飙升
- CONV_AGE 不出现长期卡死在超时区间
- 系统无连续重启、无持续性故障风暴

### 8.3 本地维护测试

操作：

- 长按 SET + UP
- 长按 SET + DOWN
- 短按 SET

验收标准：

- 可清除锁定故障
- 可清零统计项
- 短按 SET 可切换蜂鸣器开关
- OLED 单页状态与实际动作一致

## 9. 运行统计测试

检查项：

- 加热累计时长
- 制冷累计时长
- 告警次数
- 降级次数
- 停机次数
- 继电器动作次数

验收标准：

- 状态切换后统计值能正确增加
- 网页与 JSON 显示一致
- 清零操作后统计值按预期归零

## 10. 建议验收结论格式

每次联调建议记录：

- 日期
- 硬件版本
- 固件版本
- 测试人员
- 未通过项
- 临时规避措施
- 下次整改计划

建议附加：

- 构建日志文件名
- 串口监视日志文件名
- 网页关键截图文件名

## 11. 当前建议优先执行的测试项

如果时间有限，优先做以下 6 项：

1. 双探头正常采样
2. 单探头断线降级
3. 双探头失效停机
4. 加热与制冷互锁
5. 绝对高温切断
6. 掉电恢复与参数保持
7. 网页并发写入稳定性（V1 新增）

这 7 项能最快发现首版系统的大部分关键风险。

## 12. V1 已知约束

- 当前 I2C 显示驱动为 legacy I2C API。
- 已通过 `CONFIG_I2C_SUPPRESS_DEPRECATE_WARN` 抑制编译提示。
- 后续环境具备新 I2C 主机头文件后，再安排驱动迁移验证。
